# visio-people-counter

Подсчёт трафика людей по видеонаблюдению: локальный файл (mp4/avi/mkv) или
HLS-поток (`.m3u8`). Без классификации объектов — motion-based конвейер
(background subtraction → трекер → линия/зона пересечения), работающий на CPU.

**Полная инструкция по циклу работы с видео** (тестирование, калибровка, GUI,
dоводка параметров под камеру): [`docs/USER_MANUAL.md`](docs/USER_MANUAL.md)

## Установка

Требуется Python 3.10+ и системные `ffmpeg`/`ffprobe`. Окружение проекта — `.venv`:

```bash
python3 -m venv --system-site-packages .venv
.venv/bin/pip install -r requirements.txt
```

Все команды запускаются через `.venv/bin/python`.

## Конфигурация

Эталон схемы конфига — [`config.example.yaml`](config.example.yaml) (все блоки,
ключи и дефолты с комментариями: `video`, `processing`, `motion`, `objects`,
`size_profile`, `tracker`, `counters`, `output`, `debug`). Скопируйте и подстройте:

```bash
cp config.example.yaml config.yaml
```

Все координаты (линия, зона, size-профиль) заданы в нормализованных долях кадра
0..1 — конфиг переживает смену разрешения камеры. Быстрый способ получить
координаты линии/зоны — GUI-калибровка `calibrate` (см. ниже).

### Интервал кадров (`processing.frame_start` / `frame_end`)

Счётчики работают **только в указанном интервале кадров** (удобно для длинных
видео, где люди проходят только в одном отрезке):

- `frame_start: 100` + `frame_end: 250` — подсчёт в кадрах 100–250; 
- только `frame_start` — с этого кадра до конца видео;
- только `frame_end` — от начала до этого кадра **включительно**;
- ничего не задано (null) — как раньше, весь видео.

Номера кадров **0-based** (совпадают с индексом OpenCV и с тем, что показано в
окне калибратора: «кадр N»); `frame_end` — включительно. Важно: детектор 
обрабатывает ВСЕ кадры (модель фона MOG2 должна обучиться до начала интервала),
поэтому скорость прогона вне интервала та же — выигрывают только трекер и 
счётчики. Применённый интервал виден в финальной сводке (`интервал кадров: …`) 
и в шапке markdown-отчёта.

### ROI — область обработки (`processing.roi`)

ROI — **один глобальный прямоугольник** на всё видео, задающий область, которую
обрабатывает конвейер:

```yaml
processing:
  roi: [0.2, 0.3, 0.6, 0.4]   # [x, y, w, h] — доли ПОЛНОГО кадра; все в (0..1],
                              # x + w <= 1, y + h <= 1; null/отсутствует = весь кадр
```

Кроп применяется **на уровне источника** (для HLS — `ffmpeg -vf crop`, для файла —
срез кадра), поэтому весь конвейер видит ROI-кадр как полный. Важные следствия:

* **все координаты конфига** (линии/зоны/size-точки) **и события** (events.jsonl,
  отчёт) отсчитываются **от ROI**, а не от полного кадра — задавайте геометрию
  счётчиков ПОСЛЕ выбора области (в окне калибровки это автоматически);
* в финальной сводке и markdown-отчёте есть строка `ROI: x–x+w × y–y+h` (или «нет»);
* влияние на скорость: экономия CPU-этапов (детекция/трекинг/счёт — на меньшей
  площади); декодирование остаётся полным;
* ⚠️ **смена ROI после настройки геометрии сбивает линии/зоны** — проверьте их в
  режиме «все» (`v`) и при необходимости перерисуйте;
* **авто-масштаб окна**: при маленьком ROI окно calibrate/`count --gui` автоматически
  открывается увеличенным, чтобы UI был доступен (~640×320 или больше; потолок ×25);
  ручное `,`/`.` — как раньше.

Как задать в окне: `calibrate` → клавиша **`r`** (или кнопка **«roi»** в панели) →
два клика по углам прямоугольника → **Enter** — принять. После принятия источник
переоткрывается с кропом, окно показывает ROI-вид (рамка + подпись `ROI: …` в статусной
строке), при этом сохраняется текущая позиция по времени; уведомление напоминает
проверить линии/зоны. Повторный `r` — правка существующего ROI (текущий прямоугольник
показывается в окне), ESC — отмена.

## Режимы работы

### 1. Диагностика входа (`probe`)

Разрешение/fps/длительность/кодек по ffprobe; для файла дополнительно проверяется
открытие через `cv2.VideoCapture`:

```bash
.venv/bin/python -m visio_people_counter probe --video videos/demo.mp4
.venv/bin/python -m visio_people_counter probe --video https://cam.example.com/live/stream.m3u8
```

### 2. Подсчёт (`count`) — headless по умолчанию

Без окон, на максимальной скорости обработки; события печатаются в stdout и
пишутся в JSONL (`output.events_jsonl`); при обрыве HLS-потока — автоматическое
переподключение (watchdog, `video.hls.*`):

```bash
.venv/bin/python -m visio_people_counter count --config config.yaml
# разовый прогон другого видео/потока (--video переопределяет video.path из конфига)
.venv/bin/python -m visio_people_counter count --config config.yaml --video videos/demo.mp4
.venv/bin/python -m visio_people_counter count --config config.yaml --video https://cam.example.com/live/stream.m3u8
# бенчмарк: время этапов detect/track/count, p50/p95 в финале
.venv/bin/python -m visio_people_counter count --config config.yaml --bench
# thread-pipeline (headless): кадры читает отдельный поток в очередь, обработка — в main (I/O и CPU перекрываются)
.venv/bin/python -m visio_people_counter count --config config.yaml --threads --queue-size 100
```

Завершение: EOF файла → финальная сводка; стрим → `Ctrl+C` (SIGINT) — graceful stop
с финальной сводкой.

После прогона создаётся **markdown-отчёт** с итогами по каждому счётчику (линии/зоны)
i таблицей событий: автопуть `<видео>.report.md` рядом с файлом, либо явный путь из
`output.report_path` (для HLS-потока отчёт создаётся только при явном пути). В stdout —
блок `=== ОТЧЁТ ===` + путь файла.

### 3. GUI-режим (`count --gui`)

Окно с overlay по блоку `debug` конфига: bbox треков с `track_id`, необработанные
blob'ы, микс с маской движения, линии/зоны счётчиков и крупные в/out-счётчики.
`--speed` задаёт скорость воспроизведения (0.25..8; по умолчанию 1.0) — работает
только в GUI-режиме. В Qt-окне (`--backend qt`) текст счётчиков/скорости/масштаба
перенесён из кадра в статусбар (задача 20): на видео остаётся только гракция линии/зоны. В headless-окружении (нет DISPLAY/WAYLAND_DISPLAY) команда
завершается с понятной ошибкой и кодом 1.

```bash
.venv/bin/python -m visio_people_counter count --config config.yaml --gui --speed 0.5
```

**Бэкенд окна (`--backend qt|cv2`, задача 17):** как у calibrate — тот же выбор:
- `qt` (по умолчанию, если установлен PySide6) — Qt-окно: QToolBar над кадром
  («Пауза»/«+скорость»/«−скорость»/«масштаб ↓»/«масштаб ↑»/«Выход»), статусбар внизу;
- `cv2` — классическое окно OpenCV; фолбэк без PySide6 (CLI печатает предупреждение).

```bash
.venv/bin/python -m visio_people_counter count --config config.yaml --gui --backend qt --speed 2
```

**Клавиши GUI:**

| Клавиша | Действие |
|---|---|
| пробел | пауза / продолжить (последний кадр удерживается) |
| q / ESC | выход (финальная обработка) |
| + / = | скорость ×1.5 (до 8.0) |
| − | скорость ÷1.5 (до 0.25) |
| `,` / `.` | масштаб ОТОБРАЖЕНИЯ окна: пресеты 0.5 → 1 → 1.5 → 2 (уменьшить/увеличить, цикл по концам); только экран — обработка не меняется; для больших видео ставьте 0.5, чтобы окно помещалось на монитор (текущий масштаб — в статусе `scale=…x`); начальное значение — флаг `--scale` (напр. `--scale 0.75`) |

### 4. Калибровка (`calibrate`)

GUI-режим: рисование линии/зоны/size-точек мышью; в stdout печатается короткий diff
«старые → новые координаты». Size-точки — 2D «мерка роста»: два клика по верху и низу
человека в этом месте кадра (важен и x, и y); центр считается автоматически как середина
пары, рост = длина отрезка в долях высоты кадра; в конфиге это тройки `[x, y, h]` в долях кадра
(`size_profile.control_points`). Поверхность `h(x, y)` учитывает вертикальную/диагональную
перспективу — совет: 3–5 точек по всей сцене, где реально стоят/идут люди.

**Бэкенд окна (`--backend qt|cv2`, задача 16):** два бэкенда одного контроллера —
поведение, клавиши и кнопки одинаковые.
- `qt` (по умолчанию, если установлен PySide6) — нативное Qt-окно: панель из 13 кнопок
  (`QToolBar`) НАД кадром (не нарисована в кадр), статусбар внизу окна
  (`счётчик: <id> | кадр N | scale=…x | <последнее сообщение>`), цикл по QTimer с fps
  источника; установка: `.venv/bin/pip install PySide6`; весь текст (статус, подсказки
  режимов/размера/ROI, уведомления) — в статусбаре и QLabel под кадром, на видео остается
  только разметка (линии/зоны/точки/рамки), поэтому он читаем при любом зуме окна;
- `cv2` — классическое окно OpenCV (кнопки нарисованы вверху кадра); фолбэк, если PySide6
  не установлен (CLI печатает предупреждение в stdout).

```bash
.venv/bin/pip install PySide6   # опционально: Qt-бэкенд калибратора
.venv/bin/python -m visio_people_counter calibrate --video videos/demo.mp4 --backend qt
```

**Мульти-счётчики и кнопки:** вверху кадра (cv2-окно) — статусная строка
(`Счётчик: <id> (линия|зона, позиция i из N)`) и кликабельная панель кнопок,
нарисованная прямо в кадр (кириллица через `text_overlay`; в Qt-окне это QToolBar над
кадром): `линия`, `зона`, `size`, `маска`, `все` (клавиша `v`: режим просмотра
ВСЕХ счётчиков из конфига — поверх кадра рисуются все линии и зоны с размерами: у линий
длина в px и нормализованная (`{id}: 342px (0.861)`), у зон число углов и доля площади
кадра (`{id}: 5 угл., S=9.3% кадра`); текущий счётчик выделяется — чисто визуальный
режим, не влияет на apply/delete/seek), `<`/`>` (предыдущий/следующий счётчик из
`cfg.counters`, геометрия загружается для правки), `+линия`/`+зона` (новый счётчик с id
`line_N`/`zone_N` — попадает в конфиг при `[a]`), `удалить` (клавиша `x`: убирает текущий
счётчик из конфига и очищает его точки, чтобы он не «воскрес» при сохранении; после этого
окно переключается на соседний счётчик или автоматически создаёт новый той же природы),
клавиша `b` (кнопки для этого в панели нет; только в режиме «размер»: отменяет ПОСЛЕДНЮЮ
size-точку; ошибочную точку можно удалить и кликом прямо по ней — hit-радиус ~15 px на экране),
`время` (клавиша `t`, только для файла: seek к заданной секунде — набрать 0-9, Enter=OK,
ESC/q=отмена; кэш заменяется кадрами после метки, линии/зоны/счётчик не сбрасываются),
`сохранить`. Смена счётчика также по
клавишам `[` / `]` (циклически).

**Масштаб отображения:** клавиши **`,`** / **`.`** переключают пресеты 0.5 → 1 → 1.5 → 2
(уменьшить/увеличить, цикл по концам) — меняется ТОЛЬКО размер окна (масштабирование кадра
перед показом); обработка, детекция и координаты конфига всегда в исходном разрешении видео,
координаты мыши автоматически переводятся обратно. Для большого разрешения (4K и т.п.)
ставьте 0.5, чтобы окно помещалось на экран; текущий масштаб виден в статусной строке
(`scale=…x`). Можно настроить несколько линий и несколько зон: переключайтесь
`<`/`>`, добавляйте новые кнопками, один раз `[a]` — сохранит всё.

**Куда сохраняется результат [a]:**
- по умолчанию — рядом с файлом видео: `<имя_видео>.config.yaml`
  (например, `videos/demo.mp4` → `videos/demo.config.yaml`); для HLS/URL «рядом» не
  определено — в путь `--config`;
- если `--config` задан **явно** — результат пишется строго в этот файл.

**Входной конфиг (задача 12)** — порядок поиска:
1. явный `--config` (используется и как вход, и как цель сохранения);
2. `<имя_видео>.config.yaml` рядом с видео — если найден, используется и как вход,
   и как цель сохранения: правки НЕ затирают остальные блоки (motion/objects/processing,
   в т.ч. `frame_start/frame_end`) — файл дописывается, а не создаётся заново;
3. дефолты (один line-счётчик `main_line`): предупреждаем, что сохранение [a]
   создаст `<имя_видео>.config.yaml` и перезапишет его дефолтами + новой геометрией.

Если во входном конфиге задан `processing.frame_start` — калибровочное окно сразу
открывает этот кадр (seek при старте, только для файла; уведомление «переход к кадру N
(processing.frame_start)», кадр за пределами видео → старт с начала).

Входного конфига может не быть: calibrate стартует с настройками по умолчанию (один
line-счётчик `main_line`). Остальные режимы (`count`, `probe`) требуют существующий конфиг:

```bash
# результат → videos/demo.config.yaml; дальше: count --config videos/demo.config.yaml
.venv/bin/python -m visio_people_counter calibrate --video videos/demo.mp4
# явный выходной файл + другой id счётчика (по умолчанию main_line)
.venv/bin/python -m visio_people_counter calibrate --config my_conf.yaml \
    --video videos/demo.mp4 --counter-id entry_zone
# кэш из 50 кадров для листа [n/p] и после seek ([t])
.venv/bin/python -m visio_people_counter calibrate --video videos/demo.mp4 --cache-frames 50
```

**Клавиши калибровки:**

| Клавиша | Действие |
|---|---|
| `l`, затем 2 клика | линия A→B (порядок кликов = направление «in»); повторный `l` или 3-й клик — заново |
| `z`, N кликов, Enter | полигон зоны (≥3 точек) |
| `s`, два клика | size-точка «мерка роста»: кликните верх и низ человека в этом месте кадра (важен и x, и y); центр = середина пары, рост = длина отрезка в % высоты кадра; Enter — завершить набор; **клик по уже нарисованной мерке (~15 px, только когда нет ожидающего 1-го клика) удаляет её** |
| `m` | toggle маски движения (видно, что детектится; для подбора `motion.var_threshold` и т.п.) |
| `v` | toggle режима «все»: все линии/зоны из конфига поверх кадра с размерами (линия — длина в px и нормализованная; зона — число углов и доля площади кадра); текущий счётчик выделяется. Только визуал |
| `[` / `]` | предыдущий / следующий счётчик из `cfg.counters` (циклически; то же, что кнопки `<`/`>` в кадре) |
| `x` | удалить текущий счётчик (то же, что кнопка «удалить»; точки очищаются, переключение на соседний/новый) |
| `b` | отменить ПОСЛЕДНЮЮ size-точку (только в режиме «размер»; кнопки для этого в панели нет); если точек нет — уведомление «размер: точек нет» |
| `n` / `p` | следующий / предыдущий из кэша кадров (по умолчанию первые 100; размер задаётся `--cache-frames`) |
| `t`, цифры 0–9, Enter | seek к заданному времени (сек), только для файла: переходите к моменту, когда люди в нужной части кадра; после seek кэш заменяется кадрами после метки, линии/зоны не сбрасываются. ESC/q — отмена ввода |
| `a` | применить и записать в config.yaml (можно повторно после доводки; то же, что кнопка «сохранить») |
| q / ESC | выход без сохранения |

## Структура проекта

```
visio_people_counter/
├── __main__.py         # CLI: probe / count [--gui --speed --bench] / calibrate
├── config.py           # Config: dataclass + загрузка/сохранение YAML, валидация (схема = config.example.yaml)
├── video_source.py     # FileSource (cv2.VideoCapture), FfmpegPipeSource (ffmpeg-pipe + watchdog-переподключение), ffprobe
├── motion_detector.py  # MOG2/KNN background subtraction + тени/морфология + фильтры объектов → Blob'ы
├── size_profile.py     # адаптивные пороги площади: 2D-поверхность h(x, y) — высота человека в точке кадра
├── tracker_adapter.py  # Blob'ы ↔ sv.Detections(confidence=None) → SORT/ByteTrack/BoTSORT (пакет trackers), reset()
├── line_counter.py     # LineCounter + ZoneCounter: пересечение линии/зоны, антидубль (cooldown/буфер/global gap)
├── event_log.py        # JSONL-лог событий + агрегаты in/out/total и сводки
├── pipeline.py         # главный headless-цикл: источник → детекция → трекер → счётчики, тайминги/fps/lag, SIGINT, --bench
└── gui.py              # GUI-режим: overlay (cfg.debug) + окно с паузой/скоростью; headless-фолбэк
tests/                  # unittest-тесты всех модулей (без реального видео/окна)
config.example.yaml     # эталон схемы конфигурации
```

## Архитектура (конвейер)

Кадровый конвейер: **источник → детекция движения → трекинг → счётчики → лог**.
Модули готовились последовательно, за каждым — отчёт в `pi-research/`:

| Модуль | Ответственность | Отчёт |
|---|---|---|
| `config.py` | Config: dataclass + загрузка/сохранение YAML, валидация по схеме | [11](pi-research/11-task-report.md) |
