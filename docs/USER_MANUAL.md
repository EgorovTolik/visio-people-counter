# visio-people-counter — инструкция по работе

Полный цикл: от «есть видеофайл» до «настроенный подсчёт трафика», включая
калибровку, GUI и доводку параметров под реальную камеру.

> Все команды выполняются из корня проекта, интерпретатор — только `.venv/bin/python`.

---

## 1. Как это работает (кратко)

1. **Движение** — вычитание фона (`MOG2`): кадр → маска движущихся областей + теней.
2. **Фильтры** — blob'ы отбрасываются по площади, пропорциям bbox, «заполненности» и
   времени жизни (классификации объектов нет — только фильтры шума).
3. **Трекер** (`SORT` из пакета `trackers`) — даёт каждому объекту устойчивый `track_id`,
   чтобы один человек не был посчитан дважды.
4. **Счётчики** — линии A→B и/или полигональные зоны; пересечение границы подтверждённым
   треком фиксируется как событие `in` / `out`. Зона считает НЕ ТОЛЬКО пересечения
   границы, но и **появление объекта внутри неё** (в т.ч. уже стоящего при старте видео):
   новый трек, возникший внутри полигона, даёт событие `in`; уход id трека внутри зоны
   (ломка трекера) может дать повторный вход — mitigation: `tracker.lost_track_buffer`,
   cooldown. Антидубль: per-track cooldown + буфер вокруг линии + минимальный интервал
   между любыми событиями.

Команды CLI:

| Команда | Назначение |
|---|---|
| `probe --video X` | сводка по входу (разрешение, fps, длительность, кодек) |
| `count --config config.yaml` | подсчёт; headless по умолчанию, `--gui [--speed N]` — окно |
| `calibrate --video X` | GUI-настройка линии/зоны/size-точек → `<имя_X>.config.yaml` рядом с видео (или в явный `--config`) |

## 4. Этап 2. Осмотр входного видео — `probe`

```bash
.venv/bin/python -m visio_people_counter probe --video videos/demo.mp4
```

Показывает: разрешение, fps, длительность, кодек. Зачем:

- **Разрешение** — решает, нужен ли даунскейл (`processing.max_width: 1280`) для скорости.
- **fps** — для файла оставляем `effective_fps: 0` (нативный); для HLS ставим 10–15.
- **Длительность** — чтобы понимать, сколько ждать от прогона.

## 5. Этап 3. Первый быстрый прогон (без калибровки)

Чтобы сразу увидеть, «видит ли» система движение на вашем ролике:

```bash
cp config.example.yaml config.yaml   # шаблон со всеми комментариями
.venv/bin/python -m visio_people_counter count --config config.yaml
```

В stdout будут промежуточные сводки (каждые 30 с) и финальная — по счётчикам из шаблона
(линия `main_line` и зона `entry_zone`, координаты шаблонные — цифры случайные, но видно
активность). Для HLS-источника процесс останавливается `Ctrl+C` — нажатие даёт корректную
финальную сводку.

**Если нужно посмотреть глазами** — GUI:

```bash
.venv/bin/python -m visio_people_counter count --config config.yaml --gui --speed 1
```

В окне (при дефолтных `debug.show_*`): зелёные bbox подтверждённых треков с `#id`,
оранжевые — новые (`new`), линия/зона счётчиков и текущие `in/out` в левом верхнем углу,
справа сверху — `speed=…x proc=…fps scale=…x` (масштаб отображения меняется клавишами `,`/`.`).

Бэкенд окна — флаг `--backend qt|cv2` (как у calibrate): по умолчанию `qt`, если
установлен PySide6, иначе фолбэк на cv2-окно с предупреждением.

## 6. Этап 4. Калибровка — `calibrate` (главный этап настройки)

Калибровка рисует на реальных кадрах вашего видео линию/зону/size-точки мышью и записывает
координаты в конфиг.

**Входной конфиг — порядок поиска (задача 12):**

1. явный `--config` — используется и как вход, и как цель сохранения;
2. `<имя_видео>.config.yaml` рядом с видео (`videos/demo.mp4` → `videos/demo.config.yaml`):
   если найден — это и вход, и цель сохранения, поэтому повторная калибровка НЕ затирает
   ваши блоки motion/objects/processing (в т.ч. `frame_start/frame_end`) — файл
   дописывается с новой геометрией;
3. дефолты (один line-счётчик `main_line`): сохранение [a] создаст
   `<имя_видео>.config.yaml` заново (дефолты + новая геометрия) — если рядом с видео
   уже лежал «ваш» конфиг, это означает, что он не был найден по шаблону. Для HLS/URL
   «рядом» не определено — результат пишется в путь `--config`.

Если во входном конфиге задан `processing.frame_start` — окно калибровки сразу открывает
этот кадр (seek при старте, только для файла; на экране уведомление «переход к кадру N
(processing.frame_start)»; если кадр за пределами видео — уведомление и старт с начала).

Входного конфига может не быть — старт по дефолтам (один line-счётчик `main_line`):

```bash
# результат → videos/demo.config.yaml
.venv/bin/python -m visio_people_counter calibrate --video videos/demo.mp4

# явный выходной файл + другой счётчик (создаст новый блок counters[].id)
.venv/bin/python -m visio_people_counter calibrate --config my_conf.yaml \
    --video videos/demo.mp4 --counter-id entry_zone
```

Загружается кэш первых кадров видео (по умолчанию 100; размер задаётся опцией
`--cache-frames N`) — листайте его `n`/`p`, чтобы выбрать кадр, на котором хорошо видно
улицу. Если нужного момента нет среди первых кадров — используйте seek по времени
(клавиша `t` / кнопка «время», только для файла): наберите секунду и нажмите Enter,
окно подгрузит кадры после этой метки. Например: в длинном ролике люди выходят на
проход только к середине — `t`, набрать `120`, Enter, — и вы уже листаете кадры вокруг
момента, когда люди в нужной части кадра. Собранная геометрия (линии/зоны/счётчик) при
seek НЕ сбрасывается. Если заданное время больше длительности файла — seek сам сдвинется
на «конец файла − размер кэша» (чтобы после метки гарантированно были кадры), об этом
появится уведомление.

Память: кэш держится в RAM (100 кадров при 1920×1080 ≈ 600 МБ); при нехватке памяти
уменьшите `--cache-frames` (например, до 30).

Номер текущего кадра виден в статусной строке («кадр N», 0-based) — это значение
для `processing.frame_start/frame_end` при задании интервала подсчёта (см. раздел 7,
«Интервал кадров»). В cv2-окне она нарисована вверху кадра, в Qt-окне — статусбар
внизу окна.

**Qt-окно (`--backend qt`, по умолчанию при установленном PySide6):** панель из 13 кнопок
(те же имена и порядок, что у cv2-панели: `линия`, `зона`, `размер`, `roi`, `маска`,
`все`, `<`, `>`, `+линия`, `+зона`, `удалить`, `время`, `сохранить`) — над кадром, а не
нарисована в него; активный режим подсвечивается. Статусбар внизу окна:
`счётчик: <id> | кадр N | scale=…x`; последнее уведомление. **Весь текст окна — в тулбаре, статусбаре и QLabel-подсказке под кадром** (подсказка режима: «ЛИНИЯ: …», завершённые мерки «размер: N%», ожидающая мерка «мера: …px (%)» + «мерка: кликните 2-ю точку…», подсказка режима ROI). На само видео/кадр остаётся ТОЛЬКО разметка — линии, зоны, точки, рамки (она и масштабируется вместе со сценой при зуме окна `,`/`.`); текст на кадре больше не рисуется, поэтому всегда читаем независимо от масштаба отображения. Установка Qt-бэкенда:
`.venv/bin/pip install PySide6`. Без PySide6 CLI фолбэкает на cv2-окно (классическое
OpenCV-окно, кнопки нарисованы вверху кадра) и печатает предупреждение в stdout.
Поведение, клавиши и кнопки у обоих бэкендов одинаковые — таблица ниже без изменений.

### Клавиши

| Клавиша | Действие |
|---|---|
| `l`, затем 2 клика | **линия A→B**. Порядок кликов = направление «in»: первый клик — точка A (старт), второй — B (конец). Повторный `l` или 3-й клик — начать заново. |
| `z`, N кликов, Enter | **полигон зоны** (≥3 точек); Enter замыкает; повторный `z` — заново |
| `s`, два клика | **size-точка «мерка роста»**: кликните ВЕРХ и НИЗ человека, стоящего/идущего в этом месте кадра (важен и x, и y — профиль 2D). Центр точки считается автоматически как середина пары, рост = длина отрезка в % высоты кадра. Enter — завершить набор точек. В конфиге точка пишется тройкой `[x, y, h]` в долях кадра. На экране — вертикальный отрезок-«человечек» с подписью «размер: N%»; пока ждёте второй клик — маркер + пунктирное превью до курсора с текущей длиной (px / %). **Клик по уже нарисованной мерке (радиус ~15 px, только когда нет ожидающего 1-го клика) удаляет её** — так исправляют ошибочную высоту, не переделывая весь набор. |
| `r`, затем 2 клика, Enter | **ROI — область обработки**: два клика по углам прямоугольника (порядок не важен), Enter — принять: источник переоткрывается с кропом (`processing.roi` в долях ПОЛНОГО кадра), окно показывает ROI-вид с рамкой и подписью `ROI: x–x+w × y–y+h` в статусной строке, текущая позиция по времени сохраняется. После этого координаты линий/зон/size-точек и событий считаются ОТ ROI — проверьте их в режиме «все» (`v`). Повторный `r` — заново/правка существующего (текущий прямоугольник показан), ESC — отмена | 
| `b` | **отменить последнюю size-точку** — удаляет только что добавленную точку из набора (работает в режиме «размер»: если режим не включён, появится подсказка «включите режим размер»); при пустом наборе — уведомление «размер: точек нет» |
| `m` | toggle маски движения: видно, что именно детектор считает движением (основа для подбора `motion.*`) |
| `v` | **режим «все»**: поверх кадра рисуются ВСЕ линии и зоны из конфига с размерами — у линий длина в пикселях и нормализованная (`line_1: 342px (0.861)`), у зон число углов и доля площади кадра (`zone_1: 5 угл., S=9.3% кадра`); текущий счётчик выделен. Чисто визуальный режим — на apply/delete/seek не влияет |
| `[` / `]` | предыдущий / следующий счётчик из конфига (циклически); его геометрия загружается в окно для правки |
| `n` / `p` | следующий / предыдущий из кэша кадров (по умолчанию первые 100; `--cache-frames N`) |
| `t`, цифры `0–9`, Enter | **seek к заданному времени** (секунды), только для файла: режим ввода, буфер показан в кадре каждый кадр; Enter — перейти и подгрузить кадры после метки, ESC/q — отмена. Линии/зоны/текущий счётчик НЕ сбрасываются. Для HLS/URL недоступен (нет случайного доступа) |
| `a` | **применить и записать** в целевой конфиг (см. выше: рядом с видео или явный `--config`; остальные блоки сохраняются, повторное нажатие допустимо) |
| `,` / `.` | **масштаб ОТОБРАЖЕНИЯ окна**: пресеты 0.5 → 1 → 1.5 → 2 (уменьшить/увеличить, цикл по концам); только экран — обработка и координаты конфига не меняются, клики мыши автоматически переводятся в исходные координаты; для больших видео ставьте 0.5, чтобы окно помещалось на монитор (текущий масштаб — в статусной строке сверху: `scale=…x`). Начальное значение задаётся флагом `--scale` (любое число 0.05..8, напр. `calibrate … --scale 0.75`). При маленьком кадре (маленький ROI) окно автоматически открывается увеличенным (~640×320 или больше, потолок ×25), чтобы панель кнопок оставалась доступной; пресеты `,`/`.` работают поверх авто-значения |
| `q` / ESC | выход без сохранения |

### Кнопки в окне (то же самое, что клавиши)

В тулбар OpenCV/Qt свои кнопки впаять нельзя — поэтому строка кнопок рисуется прямо в кадр,
в его верхней части, над ней — статусная строка. Активная кнопка подсвечена зелёным.
Текст на русском (рендер через Pillow/TTF).

| Кнопка | Действие | Эквивалент клавиатуры |
|---|---|---|
| `линия` / `зона` / `размер` | режим рисования для текущего счётчика (начинает заново) | `l` / `z` / `s` |
| `roi` | **ROI** — режим области обработки: 2 клика по углам, Enter — принять (см. клавишу `r`) | `r` |
| `маска` | toggle показа маски движения | `m` |
| `все` | режим «все»: все линии/зоны из конфига с размерами (линия — длина px и нормализованная, зона — углы и доля площади кадра %) + мерки «размера» (вертикальные отрезки с % высоты кадра); текущий счётчик выделен; чтобы видеть картину целиком при настройке нескольких линий/зон | `v` |
| `<` / `>` | предыдущий / следующий счётчик из конфига (циклически); его линия/полигон загружаются в окно для правки | `[` / `]` |
| `+линия` / `+зона` | создать **новый** счётчик с уникальным id (`line_1`, `line_2`, … / `zone_1`, …) и сразу перейти к его рисованию; в конфиг он попадёт при сохранении | — |
| `удалить` | удалить текущий счётчик из конфига и очистить его точки (чтобы он не «воскрес» при сохранении); окно переключается на соседний счётчик или автоматически создаёт новый той же природы (линия/зона) | `x` |
| `время` | режим ввода времени для seek (секунды 0-9, Enter=OK, ESC/q=отмена); только для файла — для HLS/URL появится уведомление «seek недоступен» | `t` |
| `сохранить` | применить всё собранное и записать в целевой конфиг (diff печатается в stdout) | `a` |

**Несколько линий и несколько зон:** рисуем первую линию (`линия` → 2 клика), жмём `+зона`
(или `<`/`>` — переключение на уже существующие счётчики из конфига), рисуем зону, Enter,
и т.д. Статусная строка сверху показывает, что редактируется: «Счётчик: main_line (линия,
позиция 1 из 3)». Чтобы увидеть картину целиком — кнопка `все` / клавиша `v`: все линии
и зоны из конфига накладываются на кадр с размерами (у линий — длина в px и нормализованная,
у зон — число углов и доля площади кадра %), текущий счётчик выделен. Клик по кнопке НЕ
ставит точку линии/зоны — точки рисуются только ниже панели; подсказки перенесены в низ
кадра, красные сообщения выводятся под строкой кнопок.

### Рекомендуемый порядок действий

1. `n`/`p` — выберите 2–3 репрезентативных кадра (день/вечер, с людьми и без).
   Если среди первых кадров такого нет — `t` → секунда → Enter: seek к моменту,
   когда люди в нужной части кадра (только для файла).
2. **Линия**: `l` → клик A там, откуда люди «входят» в зону наблюдения, клик B — куда
   «уходят». Проводите линию поперек прохода/дорожки так, чтобы человек пересек её
   целиком (не по диагонали вдоль движения).
3. **Зона** (опционально, если нужно считать occupancy): `z` → клики по углам → Enter.
4. **Size-точки** (обязательно для камеры с широкой/вертикальной перспективой): `s`,
   затем «мерка роста» — ДВА клика: верх и низ человека, стоящего/идущего в этом месте
   кадра (важен и x, и y — «глубина» кадра обычно идёт по вертикали). Центр точки
   считается автоматически как середина пары, рост = длина отрезка в долях высоты кадра
   (где человек большой — ближе к камере — мерка длиннее, где мелкий — дальний план —
   короче). Совет: 3–5 точек, распределённых по всей сцене; между ними программа строит
   поверхность h(x, y). На экране завершённая «мерка» рисуется вертикальным отрезком-
   «человечком» с подписью «размер: N%»; пока ждёте второй клик — маркер первого клика
   и пунктирное превью до курсора с текущей длиной (px / % кадра).
   **Исправление ошибок:** ошиблись высотой — кликните прямо по этой «мерке»
   (радиус ~15 px; только когда нет ожидающего 1-го клика пары), и точка удалится;
   добавили лишнюю последнюю точку — клавиша `b` отменит её.
   Переделывать весь набор не нужно. Цифры 1–9 в этом режиме больше не используются.
5. **Проверка маски**: `m` — убедитесь, что люди подсвечиваются, а фон (тени от деревьев,
   мерцание) — нет. Если людей мало в маске → снижайте `motion.var_threshold`;
   если шумит всё → повышайте (см. §8).
6. **Несколько счётчиков** (опционально): кнопка `+линия`/`+зона` — новый счётчик
   (`line_N`/`zone_N`); `<`/`>` (или `[`/`]`) — переключение между существующими, их
   геометрия подгружается для правки; лишние можно убрать кнопкой `удалить` (клавиша
   `x`) — окно само переключится на соседний счётчик или создаст новый той же природы.
   Статусная строка сверху показывает текущий счётчик.
7. `a` (или кнопка «сохранить») — сохранить **всё** собранное. В stdout напечатается
   diff «старые → новые» координаты по каждому изменённому счётчику.
8. **(Опционально) ROI**: если нужно считать только часть кадра (например, проход,
   а не весь двор) — кнопка `roi` / клавиша `r`, два клика по углам области, Enter.
   Источник переоткрывается с кропом, окно сразу показывает ROI-вид. **Важно:
   выбирайте ROI ПЕРЕД рисованием линий/зон** (или перерисуйте геометрию после
   смены ROI) — все координаты отсчитываются от области обработки. В статусной
   строке постоянно видна подпись `ROI: …`; при изменении ROI появится уведомление
   «проверьте линии/зоны».

Подсказки в окне — на русском (рендер через Pillow/TTF; см. §11).

## 7. Этап 5. Основной прогон — `count`

```bash
.venv/bin/python -m visio_people_counter count --config config.yaml
```

- **Headless по умолчанию** (максимальная скорость, окно не открывается).
- Файл: при EOF программа сама завершается с финальной сводкой.
- HLS: работает до `Ctrl+C`, после чего печатает финальную сводку.

### Результаты

1. **stdout** — промежуточные сводки каждые `output.summary_interval_s` и итоговая:
   по каждому счётчику `in / out / total`.
2. **`results/events.jsonl`** (путь из `output.events_jsonl`) — по одной JSON-строке на
   событие; удобно для отладки пересчётов/дублей:

```json
{"ts_wall":"2026-09-11T...Z","t_wall":143.2,"counter_id":"main_line",
 "direction":"in","track_id":7,"frame_index":2148,"x_px":512.3,"y_px":288.7,"t_video_s":14.3}
```

Поля: `counter_id` — какой счётчик; `direction` — in/out; `track_id` — трек (дубли =
одни и те же id подряд с близким `t_wall`); `frame_index` / `t_video_s` — где в записи
было событие (можно перемотать и проверить глазами).
3. **Markdown-отчёт** — человекочитаемый файл с итогами по каждому счётчику и таблицей
   событий, создаётся в конце любого прогона (EOF/`Ctrl+C`, даже если событий 0). См.
   раздел «Отчёт» ниже.

### Интервал кадров (`processing.frame_start` / `frame_end`)

Для длинных видео можно включить счётчики **только в нужном интервале кадров**:

```yaml
processing:
  frame_start: 100   # первый кадр подсчёта (0-based, включительно); null = с первого
  frame_end: 250     # последний кадр подсчёта (0-based, включительно); null = до конца
```

Три случая (+ «ничего»):

- **ничего не задано** (null/null) — подсчёт с первого кадра до последнего (как раньше);
- **только `frame_start`** — с этого кадра до конца видео;
- **только `frame_end`** — от начала до этого кадра **включительно**;
- **оба** — от `frame_start` до `frame_end` включительно.

Номера кадров **0-based**: совпадают с индексом кадра OpenCV и с тем, что показано в окне
калибратора (строка статуса: «кадр N» — подставьте это значение в конфиг). Чтобы увидеть
номер нужного момента: `calibrate --video …`, листайте `n`/`p` или seek по времени `t`,
запомните «кадр N» из статусной строки.

⚠️ Детектор при этом обрабатывает **все** кадры — модель фона MOG2 должна обучиться ДО
начала интервала, иначе первый кадр интервала будет полон ложного foreground. Скорость
прогона вне интервала та же; внутри интервала включаются трекер и счётчики. В GUI-режиме
(`count --gui`) статус показывает `подсчёт: ждём кадр N` до старта и
`подсчёт завершён (до кадра M)` после окончания — видео продолжает проигрываться.
Применённый интервал виден в финальной сводке (`интервал кадров: 100–250 (подсчёт)` или
`весь`) и в шапке markdown-отчёта.

### ROI — область обработки (`processing.roi`)

Один глобальный прямоугольник `[x, y, w, h]` в долях **полного** кадра; кроп
применяется на уровне источника (HLS — `ffmpeg -vf crop`, файл — срез кадра),
поэтому весь конвейер видит ROI как полный кадр:

```yaml
processing:
  roi: [0.2, 0.3, 0.6, 0.4]   # null/отсутствует = весь кадр
```

* Задание в окне: `calibrate` → клавиша `r` / кнопка `roi` → 2 клика по углам →
  Enter (подробнее — §6). После принятия окно сразу на ROI-виде: рамка + подпись
  `ROI: x–x+w × y–y+h` в статусной строке.
* **Координаты счётчиков и событий — в системе ROI** (отсчитываются от кропа);
  в events.jsonl/отчёте `x_px/y_px` — пиксели ROI-кадра. В шапке отчёта при этом
  есть примечание об этом.
* **Авто-масштаб окна (задача 14)**: если ROI маленький, окно калибратора и
  `count --gui` автоматически открывается увеличенным так, чтобы UI был доступен
  (~640×320 или больше; потолок авто-увеличения ×25; ручной `--scale` — минимум).
  В calibrate при этом в окне появляется уведомление «малое изображение W×H —
  окно увеличено до …x для доступного UI», в `count --gui` текущий масштаб виден
  в статусной строке `scale=…x`; ручное `,`/`.` — как раньше, поверх авто-значения.
* ⚠️ Смена ROI после настройки геометрии сдвигает линии/зоны относительно сцены —
  выбирайте ROI до калибровки или перерисуйте геометрию (проверка — режим «все», `v`);
  при изменении ROI в окне появляется уведомление.
* Влияние на скорость: детекция/трекинг/счёт работают на меньшей площади
  (экономия CPU-этапов); декодирование видео остаётся полным.
* Применённый ROI виден в финальной сводке (`ROI: 0.2–0.8 × 0.3–0.7` или `ROI: нет`)
  и в шапке markdown-отчёта (строка `- ROI: …`).

### Отчёт (`output.report_path`)

В конце прогона пишется markdown-отчёт; в stdout — блок `=== ОТЧЁТ ===` + путь файла.

- **Автопуть** (когда `output.report_path: ""`): рядом с исходным видео —
  `<видео>.report.md` (например, `videos/demo.mp4` → `videos/demo.report.md`). Для
  HLS/URL автоотчёта нет — задайте путь явно.
- **Явный путь**: `output.report_path: reports/run.md` в конфиге (родительские каталоги
  создаются; существующий файл перезаписывается).

Содержимое: шапка (дата запуска, длительность/кадры/fps видео, причина остановки),
таблица «Итоги по счётчикам» (in/out/total по каждой линии и зоне + строка ВСЕГО,
совпадает со строкой «Сводка» в stdout; счётчик без событий — нули) и разделы
«События: <id>» с таблицей каждого события (время в видео, направление, track_id,
координаты, номер кадра).

### Профилирование скорости

```bash
.venv/bin/python -m visio_people_counter count --config config.yaml --bench
```

В финале — p50/p95 по этапам `detect / track / count` и общий fps. Если детект медленный —
снижайте `processing.max_width` или `effective_fps`.

## 8. Этап 6. GUI-просмотр — `count --gui`

```bash
.venv/bin/python -m visio_people_counter count --config config.yaml --gui --speed 2
```

### Клавиши окна

| Клавиша | Действие |
|---|---|
| пробел | пауза / продолжить (в статусе появится `[ПАУЗА]`) |
| `+` / `=` | быстрее ×1.5 (максимум 8×) |
| `-` | медленнее ÷1.5 (минимум 0.25×) |
| `,` / `.` | масштаб ОТОБРАЖЕНИЯ окна: пресеты 0.5 → 1 → 1.5 → 2 (уменьшить/увеличить, цикл по концам); только экран — обработка и детекция не меняются; для больших видео ставьте 0.5, чтобы окно помещалось на монитор. Начальное значение — флаг `--scale` (напр. `count … --gui --scale 0.75`). При маленьком кадре (маленький ROI) масштаб стартует автоматически увеличенным (~640×320 или больше, потолок ×25; текущий — в статусе `scale=…x`) |
| `q` / ESC | выход (с финальной сводкой) |

**Бэкенд окна — флаг `--backend qt|cv2` (задача 17; тот же выбор, что у calibrate):**

- `qt` (по умолчанию при установленном PySide6) — Qt-окно: кнопки над кадром (QToolBar):
  **Пауза** (checkable), **+скорость**, **−скорость**, **масштаб ↓**, **масштаб ↑**, **Выход**
  — вызывают те же действия, что клавиши ниже; статусбар внизу: `speed=…x proc=…fps
  scale=…x [ПАУЗА]` + строка счётчиков «счётчики: `<id>: in=N out=M`» (задача 20) +
  последнее событие. Текст счётчиков/скорости/масштаба перенесён из кадра в статусбар —
  на видео остаётся ТОЛЬКО гракция линии/зоны (`show_counters`); клавиатура окна работает
  так же (пробел/+/−/,/. /q);
- `cv2` — классическое окно OpenCV; фолбэк, если PySide6 не установлен (CLI печатает
  предупреждение: `.venv/bin/pip install PySide6`).

```bash
.venv/bin/python -m visio_people_counter count --config config.yaml --gui --backend qt --speed 2
```

**Встроенная тулбар-панель OpenCV 5** (только cv2-окно; иконки над кадром): стрелки/зум —
панорамирование и масштаб окна; **дискета = «Save current image» (Ctrl+S)** — сохранить
текущий *кадр* через системный диалог (имя по умолчанию `<окно>_screenshot_<дата>.png`);
clipboard — копия кадра в буфер. ⚠️ Это НЕ сохранение конфига: конфиг калибровки пишется
клавишей **`a`** без диалога. Встроенный в колесо opencv Qt видит системную GTK-тему/шрифты
автоматически (`apply_qt_env()` в `gui.py`).

Статус справа сверху: `speed=…x proc=…fps scale=…x [ПАУЗА]` — `scale` — масштаб отображения
(клавиши `,`/`.`);
`proc < speed` при speed>1 значит кадры выбрасываются.

### Что показывает и чем управлять (блок `debug` в конфиге)

| Флаг | Что рисует | Когда включать |
|---|---|---|
| `show_bboxes: true` | bbox треков + `#track_id` (зелёный — подтверждённый, оранжевый — `new`) | почти всегда |
| `show_counters: true` | линии/зоны (графика — всегда); `in/out` в углу рисуются только
  в cv2-окне и headless. В Qt count-окне (`--backend qt`) `in/out` перенесены в статусбар
  «счётчики: …», на кадре остаётся только гракция линии/зоны (задача 20) | почти всегда |
| `show_all_blobs: true` | **все** blob'ы до фильтров (пурпурные) | когда нужно понять, что отбрасывается фильтрами |
| `show_mask: true` | микс кадра с маской движения 50/50 | подбор `motion.*` |
| `save_debug_frames_dir: debug/` + `debug_frame_step: 10` | сохранение каждого N-го кадра в папку (headless: обработанный; GUI: с overlay) | «замороженные» кадры для разбора без повторного прогона |

## 9. Этап 7. Доводка параметров под реальное видео

Смотрите на `show_mask` / `show_all_blobs`, гоняете headless, сверяете `events.jsonl`
и счётчики с тем, что реально видно в ролике (перемотка по `frame_index`). Итеративно:
поменяли параметр → перегнали → сравнили.

### Симптом → что крутить

| Симптом | Параметры (блок) |
|---|---|
| **Дальних/мелких людей не видно** | `motion.var_threshold` ↓ (32→16–24); `objects.min_area_fraction` ↓; `size_profile.enabled: true` + точные size-точки, `size_profile.k_min` ↓ (0.2→0.15) |
| **Много шума**: ветки, дождь, блики, качка камеры | `motion.var_threshold` ↑ (до 48–64); `objects.morph_open` выше (`[5,5]`–`[7,7]`); `objects.min_fill` ↑; `objects.min_lifetime_frames` ↑ (3→5) |
| **Считаются машины** | `objects.aspect_ratio_range` сузить до `[0.3, 1.2]`; `objects.max_area_fraction` ↓ (машины большие); `min_fill` ↓ не помогает — машины заполняют bbox хорошо, rely на aspect/area |
| **Двойной подсчёт одного человека** | счётчик: `cooldown_s` ↑ (2→4), `buffer_width_scale` ↑; `tracker.lost_track_buffer` ↑ (чтобы трек не рвался и не создавался новый id) |
| **Трек «рвётся»**, один человек = несколько id | `tracker.lost_track_buffer` ↑ (60→90–120); `tracker.minimum_iou_threshold` ↓ (0.3→0.2) при быстром движении/низком fps | 
| **В зоне дубли** (человек стоит внутри, трекер меняет id → новый id = повторный "in") | ожидаемое поведение зоны (задача 09: появление внутри считается входом); `tracker.lost_track_buffer` ↑ и `cooldown_s`/`min_global_gap_s` счётчика ↑ |
| **Человек, стоящий у линии, «моргает»** счётчиком | `min_global_gap_s` ↑; ensure что линия не проходит по месту остановки людей |
| **Тени считаются людьми** | `motion.detect_shadows: true`, `motion.shadow_threshold` подобрать (130–250): тени имеют значение маски 127 — порог отделяет тень от объекта; проверить через `m` в calibrate |
| **Медленно** | `processing.max_width: 1280`; HLS: `effective_fps: 10–15`; смотреть `--bench` |

### Размерные фильтры и size_profile (широкий угол)

Без `size_profile` действует глобальный `objects.min_area_fraction` — один порог на все
дистанции, дальних людей он неизбежно режет. С включённым блоком:

- в каждой точке кадра локальный порог = `k_min × (рост человека в px)²` — т.е. и ближнего,
  и дальнего считается по одному правилу «насколько большой здесь должен быть человек»;
- рост моделируется как функция от ОБЕИХ координат: `h(x, y)`. Это важно для
  вертикальной/диагональной перспективы: «глубина» сцены часто идёт по вертикали кадра,
  и одного x недостаточно. Формат точки — тройка `[x, y, h]` в долях кадра;
- подгонка поверхности по числу точек: 4+ — `a + b·x + c·y + d·x·y` (наименьшие квадраты),
  3 — плоскость, 2 — интерполяция вдоль отрезка, 1 — константа. Старые пары `[x, h]`
  читаются с миграцией `y = 0.5` (warning в stdout) — перекалибруйте при возможности;
- size-точки задают рост человека в конкретных местах сцены — каждая ставится двумя
  кликами «меркой роста» (верх/низ человека; см. §6, шаг 4); совет: 3–5 точек по всей
  сцене, где реально стоят/идут люди;
- после калибровки обязательно `size_profile.enabled: true` в конфиге.

## 10. HLS-поток (live)

```yaml
video:
  type: hls
  path: https://cam.example.com/live/stream.m3u8
  hls:
    reconnect_attempts: 0     # 0 = переподключаться вечно (рекомендация)
    reconnect_backoff_s: 5.0
processing:
  effective_fps: 12           # для стрима разумно 10–15 (меньше нагрузка)
```

Запуск тот же: `count --config config.yaml`. Задержка потока не оптимизируется
(по ТЗ не важна). Обрывы — watchdog переподключает ffmpeg; события пишутся в тот же
`events.jsonl` (appends), промежуточные сводки каждые 30 с. Стоп — `Ctrl+C`.

⚠️ Markdown-отчёт для стрима создаётся **только при явном** `output.report_path`
(автопути `<видео>.report.md` нет — локального файла видео нет). Задайте, например,
`output.report_path: reports/live.md`, чтобы получать файл с итогами после каждого стопа.

## 11. Частые проблемы

| Проблема | Решение |
|---|---|
| `файл не найден` при `count` | конфиг обязателен: сначала `calibrate --video X` (создаст `X.config.yaml` рядом с видео) или `cp config.example.yaml config.yaml`. Только `calibrate` умеет старт без файла. |
| GUI не открывается (`GUI недоступен…`) | нужен X11/Wayland-дисплей: запустите на машине с графической сессией; headless-режим работает без дисплея. |
| Кириллица в подписях окна | поддерживается через Pillow + TTF (`text_overlay.py`); если Pillow/шрифт недоступны — тихий фолбэк на ASCII с «?»; свой шрифт: переменная окружения `VPC_FONT_PATH=/path/to/font.ttf` (нужна кириллица, напр. DejaVu Sans) |
| Счётчики нулевые, но bbox'ы рисуются | линия/зона стоят там, где треки не пересекают их: перегоните `calibrate` по кадрам с людьми (`n/p`) |
| ffmpeg-ошибки для HLS | проверьте URL вручную: `ffprobe <url>`; заголовок/аутентификация — укажите в URL или добавьте поддержку позже |
| Падение по памяти на длинном файле | включите `processing.max_width` и/или `effective_fps`; замерьте `--bench` |
