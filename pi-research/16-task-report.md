## Таблица клавиш

**GUI-режим (`count --gui`)**

| Клавиша | Действие |
|---|---|
| пробел | пауза / продолжить (кадр удерживается) |
| q / ESC | выход (финальная обработка: destroyAllWindows + pipeline.close()) |
| + / = | скорость ×1.5 (до 8) |
| − | скорость ÷1.5 (до 0.25) |

Перемотка «r» не реализована — по ТЗ задачи 16 не нужна (стрим); для файла при необходимости листается тем же `--speed`.

**Калибровка (`calibrate`)**

| Клавиша | Действие |
|---|---|
| l, затем 2 клика | линия A→B выбранного счётчика (порядок кликов = направление «in»); повторный l — начать заново; 3-й клик — также заново |
| z, N кликов, Enter | полигон зоны (≥3 точек, иначе сообщение об ошибке) |
| s, клик, цифра 1–9 | size-точка: x из клика, высота человека = цифра×5% высоты кадра (1=5% … 9=45%); Enter — завершить набор |
| m | toggle маски движения (live-подстройка порога: видно, что детектится) |
| n / p | следующий / предыдущий из загруженных кадров (первые ≤20; для HLS — первые кадры) |
| a | применить и записать в config.yaml (`Config.save`, остальные блоки сохраняются); печатает diff «старые → новые»; можно нажать повторно после доводки |
| q / ESC | выход без записи (печать предупреждения, если [a] не нажимался) |

Один `--counter-id` задаёт ОДИН счётчик: переключение l↔z сбрасывает набросок другого типа (линия и зона с одним id — дубликат, config это запрещает). Size-точки независимы от линии/зоны.

## Что проверить вручную владельцу (пошагово)

1. В среде **с дисплеем** (X11/Wayland): `cp config.example.yaml config.yaml`, поправить `video.path`.
2. `python -m visio_people_counter calibrate --config config.yaml --video <видео> --counter-id main_line`:
   * клавиша `l` → 2 клика (A сверху-слева, B снизу-справа — направление «in»); зелёная линия с подписями A/B;
   * клавиша `m` — маска движения: убедиться, что «люди» выделены (при плохом пороге подстроить `motion.var_threshold`/`objects.min_area_fraction` в конфиге и перезапустить calibrate);
   * клавиша `s` → клик по x-позиции дальнего человека → цифра (напр., 2 = 10%) — жёлтый вертикальный отрезок нужной длины;
   * для зоны: `z` → 4+ клика → Enter (оранжевый замкнутый полигон);
   * `a` — в stdout diff «старые → новые»; проверить `git diff config.yaml` (или diff руками): координаты нормализованы 0..1, остальные блоки не тронуты;
   * перезапустить calibrate — новая линия должна уже отображаться при `l`/сравнении по счётчику.
3. `python -m visio_people_counter count --gui --speed 0.5 --config config.yaml`: окно с bbox+track_id, линией и крупными in/out в углу; пробел — пауза (счётчики видны на застывшем кадре); `+`/`−` меняют скорость в статусной строке; при пересечении линии stdout печатает «СОБЫТИЕ ...»; q — выход.
4. На headless-машине: те же команды дают ясную ошибку «нет дисплея для GUI-режима» и rc=1; `count` без `--gui` работает как раньше.

## Ограничения headless-окружения

* В этом контейнере тесты и CLI-проверки выполнены **без реального окна**: `available()` не создаёт окно (только env + `cv2.getBuildInformation()`), overlay/calibrate-логика — чистые функции. Интерактивный цикл (`imshow`/`setMouseCallback`) в headless не прогонялся — см. «ручную проверку» выше.
* Окружение контейнера содержит устаревшую переменную `DISPLAY=:0` при отсутствии X-сервера: `available()` вернёт True, а `imshow` упадёт — это ожидаемое поведение (проверка «намеренно» не создаёт окно, т.к. оно мигнуло бы в тестах); владелец увидит штатную ошибку OpenCV.
* cv2 собран с **QT5** (`GUI: QT5`, GTK NO) — окна должны работать под X11 и Wayland (Qt5). Для `opencv-python-headless` `available()` корректно вернёт False по строкам build-info.
* Скорость `--speed`/клавиши ограничена 0.25..8; при fps обработки < fps видео темп не гарантирует realtime (sleep только положительный) — окно просто идёт быстрее реального времени, как и задумано.
