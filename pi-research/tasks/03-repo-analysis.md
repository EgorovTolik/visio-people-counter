Проект: подсчёт человеческого трафика; ввод HLS URL или файл; уличная камера, широкий угол
(разный размер объектов); трекинг — вспомогательный механизм против двойного счёта.
Цель разбора — понять, ЧТО именно взять в нашу реализацию (архитектура, алгоритм линии,
параметры), а не копировать код.

## Твоя задача
1. **Клонировать** (shallow: `git clone --depth 1`) в /home/anatoliy/PiProjects/visio-people-counter/references/repos/:
   - JovanSk/yolov8-line-crossing-counter
   - roboflow/trackers
   - FoundationVision/ByteTrack
   - Gupu25/PeopleCounter (⚠️ без лицензии — read-only референс логики, код НЕ копировать)
   Каталог references/repos уже в .gitignore. Каждое клонирование с timeout 120 сек;
   если репо не склонировалось — отметь в отчёте и продолжай.

2. **Разобрать каждый репо** (read/grep/find, -maxdepth): для каждого:
   - структура проекта (ключевые файлы, размер кода LOC по основным скриптам);
   - пайплайн: как читается видео/стрим (есть ли поддержка URL/HLS? какой механизм),
     детекция (MOG2/YOLO/другое) — точные имена функций и файлов;
   - логика подсчёта: где именно проверка пересечения линии (показывать фрагменты кода
     10–30 строк с путём к файлу): как считается направление, есть ли защита от двойного
     срабатывания (cooldown/flag/hysteresis), как обрабатываются разные размеры объектов;
   - трекер: какой и как подключён, какие параметры выкручены;
   - зависимости (requirements.txt/setup.py) — что из них тяжёлое (GPU/torch);
   - лицензия и практические ограничения.

3. **Сравнительный синтез** (самое важное): таблица "механизм → реализация в репо A/B/C/D",
   по механизмам: ввод стрима; детекция движения; counting line; антидубль; трекер;
   адаптация к размерам. Затем список конкретных заимствований для нашего проекта:
   "взять из X: <механизм>, файл, функция" + что придётся писать самим с нуля.
